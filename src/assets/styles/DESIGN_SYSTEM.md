# 视觉设计方案 (Design System)

参考对象：https://www.huawei.com/en/ 的品牌语言（未做实时截图比对，
基于其公开、稳定的品牌规范：标志性红色、黑白极简基调、大幅图像式
Hero、克制的网格排版）。本方案把这套语言落地为本 CMS 的默认主题
视觉系统，而不是照搬其页面结构——内容模型不同（本站是多站点/多栏目
资讯型 CMS，不是企业官网的产品线导航），所以复用的是"克制、大图、
强对比"的设计原则，结构服务于我们自己的数据（栏目 + 文章）。

## 1. 色彩 Token

| Token | 值 | 用途 |
|---|---|---|
| `--brand-ink` | `#1A1A1A` | 主文字、激活态导航文字 |
| `--brand-charcoal` | `#2B2B2E` | 深色页脚背景（专用，不再借用 `--brand-ink`） |
| `--brand-red` | `#C7000B` | 唯一强调色——签名元素专用，不做装饰性滥用 |
| `--brand-paper` | `#FFFFFF` | 主背景、导航条背景 |
| `--brand-mist` | `#F5F5F6` | 次级区块背景，与纯白拉出层次 |
| `--brand-steel` | `#6B6B6F` | 次级文字（摘要、日期、面包屑）、导航默认态文字 |
| `--brand-line` | `#E5E5E7` | 分隔线，替代旧代码里到处出现的 `#dedfe2` / `#ccc` 等零散灰 |

> **修正记录**：第一版把导航条和页脚都设成 `--brand-ink`（近黑），
> 实际效果是头尾两端都是重色块，观感比 Huawei 官网实际的"白底导航 +
> 深灰页脚"沉重得多——这是我在没有截图比对的情况下，把"黑白极简"
> 里的"黑"过度理解成了"大面积黑色背景"，而不是"黑色仅用于文字和
> 强调"。现已修正：导航条改回 `--brand-paper`（白），页脚改用独立的
> `--brand-charcoal`（深灰，非纯黑），`--brand-ink` 收回只做文字色用途。

**为什么是这六个**：红黑白是 Huawei 品牌最不可替代的三个符号，直接
沿用是"引用真实来源"而不是"随手选一个科技感配色"。`mist` / `steel`
/ `line` 三个中性灰阶是为了让长列表型资讯页（本站的核心内容形态）
有呼吸感，避免纯黑白对比在大段文字区域显得生硬。

## 2. 字体

- **展示字体（Display）**：`"Barlow Semi Condensed"`，用于大标题、
  Hero 文案、数字/日期。半窄体本身自带"工程感/精密感"，比常规无衬线
  更贴近科技企业的气质，同时窄体让长中文栏目名和英文标题混排时不易
  换行错位。
- **正文字体（Body）**：`"Noto Sans SC"`（西文自动回退到其 Latin
  部分）。这不是随便选的"看起来干净"的无衬线——本站栏目/文章标题
  几乎全是中文，选一个专门优化过中日韩排版的字体族，而不是让中文
  字符硬挂在一个西文字体的兜底字重上，这是这个具体项目该做的选择，
  换成纯英文站点这个决策就不成立。
- **工具字体（Utility）**：正文字体的 Light/Regular 字重，用于说明性
  文字（`eyebrow` 标签、图注、面包屑），不引入第三套字体族，保持克制。

字重规则：展示字体只用 **600/700**，正文只用 **400/500**，禁止在同一
个页面里出现两种字体各自的中间字重——避免"看起来什么字重都试了一遍"
的杂乱感。

## 3. 版式概念

```
┌──────────────────────────────────────────────┐
│  LOGO      栏目 栏目 栏目 栏目 栏目    🔍 👤     │  <- 导航条，白底 + 底部发丝线，
├──────────────────────────────────────────────┤     当前栏目下方 2px 红线
│                                                │
│   [ 全幅图片 ]                                 │
│                            大标题               │  <- Hero：取当前站点
│                            摘要一行              │     第一个栏目的头条
│                            [红色细线] 阅读全文 → │     文章，左图右文字
│                                                │     或图文叠加两种之一
├──────────────────────────────────────────────┤
│ ── 栏目名 ────────────────────  更多 →          │  <- 每个 inList 栏目一节
│ ┌───────────┐ ┌───┐┌───┐┌───┐                 │     左：大卡片(头条)
│ │  头条大图  │ │小 ││小 ││小 │                 │     右：3~4 条列表式
│ │  标题/摘要 │ │条 ││条 ││条 │                 │     （对应 ArticleList
│ └───────────┘ └───┘└───┘└───┘                 │      现有的数据结构）
├──────────────────────────────────────────────┤
│  charcoal 背景页脚：链接列 / 联系方式 / 备案信息    │
└──────────────────────────────────────────────┘
```

这个"大卡片 + 小列表"的非对称网格，直接对应 Huawei newsroom 类页面
常见的 Featured/Latest 分栏，同时刚好复用本站 `ArticleList` /
`ArticleMoreList` 已有的数据结构（第一条 = 头条，其余 = 列表），
不需要改后端接口或数据模型。

## 4. 签名元素 (Signature)

**一条 4px 的红色细线**，只出现在三处，绝不作为通用装饰：

1. 主导航当前激活栏目的下划线；
2. 每个内容分区标题（eyebrow）左侧的竖线；
3. Hero 区"阅读全文"链接上方的短横线。

红色在整个设计里只做这一件事——标记"这里有一条可以往下走的路径"
（当前所在位置 / 章节起点 / 行动点），不用于按钮底色、大色块背景
或图标着色。这是从 Huawei 品牌里提炼出的用色纪律（红色克制、精准，
从不铺满），也是让页面在只有黑白灰的大面积区域里，红线出现的三次
都真正被注意到的原因——用得越少，越显眼。

**补充**：导航条改回白底后，激活栏目的文字本身、以及导航文字/右侧
搜索登录图标的 **hover** 态，也一并使用红色（见 `header.vue`）。这不算
新增第四处独立用法——白底导航下"下划线"这一个视觉信号在浅色背景上
不够醒目，需要文字本身同步变红才能维持"标记当前位置"这同一件事的
辨识度；hover 态变红则是同一枚"位置标记"信号在交互前的预告，两者都
从属于第 1 条规则，而不是又找了个新地方用红色。真正新增的用色场景
仍然只有原来的三处结构性位置。

## 5. 落地范围

本次实际修改的文件：

- `src/assets/styles/cms.css` —— 全局 Token + 基础排版 + 可复用的
  section / card / eyebrow 工具类，**与仓库里的原始文件合并**（原始
  内容由用户提供后核对过，不再是未经比对的整体替换）。合并时发现并
  修复了两处因为早期"整体替换"草稿而产生的真实回归，记录在案：
  - `--hover-color`（`myMenu.vue` 直接依赖的悬停色变量）在早期草稿
    里被漏掉，会导致该处 hover 静默失效（不报错，只是不生效）；
  - `--news-picture-width` / `--news-list-width` / `--pic-list-width` /
    `--media-width` 原本定义在 `views/web/index.vue` 的一个非 scoped
    `<style>` 块里，该文件被重写为纯主题加载器后这个块被整个删除，
    其中 `--pic-list-width` 仍被未改动的 `article/index.vue` 使用。
    现已把这几个全局自定义属性迁移到 `cms.css`（更合适的归属地），
    修复了这处回归。
  - `.article-main-body` / `.category-header` / `.elImage-category` /
    `.search-result` 等原有类保持原样，因为 `theme/default/*.vue` 和
    `article/search.vue` 仍在直接使用这些类名。
- `src/views/web/header/header.vue` —— 导航条视觉重做，Vue 逻辑
  （菜单数据、搜索框开关等）保持不变。
- `src/views/web/footer/index.vue` —— 页脚改为 ink 背景 + 结构化
  三栏，数据绑定不变。
- `src/views/web/theme/default/index.vue` —— 首页改为 Hero + 分区
  网格布局。
- `src/views/web/article/list.vue` —— 首页头条区（大图 + 列表）的
  卡片视觉。

**不修改**：`theme/butterfly/*`（未要求，且它的全屏 Banner 定位和本次
Hero 概念冲突，需要单独设计，不在本次范围内）、`ArticleMoreList` /
分类列表页（视觉上会自动继承 `cms.css` 的 Token 和字体，保持品牌
一致，但卡片结构本次不动）。
